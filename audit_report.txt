# LexAI - Complete Technical Audit

## 1. PROJECT OVERVIEW
LexAI is an AI-powered legal document assistant designed to help users quickly understand complex legal contracts and documents. The target users are legal professionals, students, and everyday individuals who need to extract key terms and risks from lengthy contracts without reading them manually. Currently, the application allows users to register an account, upload PDF and DOCX files, extract text from them, and send that text to Google's Gemini AI to generate a structured JSON analysis containing risks, obligations, and summaries. The final intended system will feature a Retrieval-Augmented Generation (RAG) chatbot allowing users to ask specific questions about their documents. The current workflow involves: User Registration -> Login -> File Upload -> Backend Text Extraction -> AI Analysis Trigger -> Gemini Processing -> Storing Results in MySQL -> Displaying a formatted report to the user.

## 4. BACKEND ARCHITECTURE
LexAI uses the Application Factory Pattern (create_app in app.py).
Extensions (extensions.py) creates empty instances to prevent circular imports.
App Factory binds them. Blueprints modularize routing.
Request Flow: Browser POSTs file -> upload route -> save_uploaded_file -> text extraction -> DB commit -> redirect to analysis page.

## 5. DATABASE ARCHITECTURE
Database Engine: MySQL 9.6
Table 1: users (id, name, email, password_hash, role, created_at, updated_at)
Table 2: documents (id, user_id, filename, file_path, file_type, status, extracted_text) -> Belongs to User
Table 3: document_analysis (id, document_id, user_id, JSON columns for parties, clauses, risks, etc.) -> One-to-One with Document

## 6. AUTHENTICATION & SECURITY
Implemented via Flask-Login and Flask-Bcrypt. Passwords hashed before saving. Sessions managed via cookies.
Weaknesses: SECRET_KEY fallback in config.py, missing CSRF protection on raw HTML forms, admin_required decorator not fully implemented.

## 7. DOCUMENT UPLOAD SYSTEM
Validation checks PDF/DOCX extension. Size limit 15MB. Secure storage using uuid4 in uploads/<user_id>/<uuid>/. Ownership checked on every access/delete request.

## 8. PDF & DOCX TEXT EXTRACTION
PDF: PyMuPDF (fitz) extracts text page by page.
DOCX: python-docx iterates through paragraphs.
Stats: Word and character counts calculated via python split/len. No OCR for scanned images.

## 9. AI / GEMINI INTEGRATION
Model: gemini-3.6-flash.
SDK: google-genai (v0.3.0).
Flow: Text truncated to 500k chars -> sent to Gemini with JSON mime_type config -> parsed into DocumentAnalysis MySQL object.
Error Handling: try/except catches JSONDecodeError, rolls back DB session.

## 10. AI PROMPT / ANALYSIS LOGIC
Instructs Gemini to return strict JSON: document_type, summary, parties, key_clauses, important_dates, obligations, risks, red_flags, financial_terms, termination_conditions, rights, recommendations, confidence, disclaimer.
